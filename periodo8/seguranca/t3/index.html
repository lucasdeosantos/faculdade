XSS: Cross-Site Scripting

Como o ataque funciona, uma demonstração prática e como se defender

Lucas Santos, Rafael Urbanek, Vitor Cumim

Começar Ir direto para a demonstração
Conceito

O que é XSS

Vulnerabilidade que permite a execução de scripts maliciosos no navegador da vítima por meio de conteúdo não tratado adequadamente.

Conceito

Como o ataque funciona

1

Injeção

O atacante insere conteúdo malicioso em um campo, comentário ou link do site.

2

Execução

O conteúdo é incorporado à página e executado no navegador da vítima.

3

Impacto

O script pode acessar dados, modificar a página ou realizar ações não autorizadas.

Três tipos de XSS

Onde o payload passaQuem é atingido
RefletidoVai na requisição HTTP e é refletido na resposta, sem ser armazenado.Quem abre o link do atacante
ArmazenadoÉ salvo no servidor, como em comentários, e executado quando a vítima acessa a página.Todo visitante da página
Baseado em DOMO JavaScript do cliente manipula dados no DOM de forma insegura, sem depender do servidor.Quem abre o link manipulado
Ataque

O ataque, passo a passo

  1. Achar um campo que devolve a entrada na página (busca, comentário, URL).
  2. Testar um payload simples, como uma imagem com onerror.
  3. Montar o payload real: ler o cookie ou alterar a página.
  4. Entregar: link para a vítima ou comentário salvo no site.
  5. O navegador da vítima executa e envia o resultado ao atacante.
// payload alerta de ataque
<img src=x 
      onerror=('Você está sob ataque!')>

Demonstração: o ataque no site

  1. Clique em "Uso normal"
  2. Clique em "alert()"
  3. Clique em "Roubar sessão"
  4. Teste "Phishing" e as abas Armazenado e DOM
Defesa

Como se defender

Nenhuma defesa isolada basta. A proteção vem de camadas que se complementam.

1. Tratar a entrada

Codificar a saída

Tratar o dado conforme o contexto: HTML, atributo, JavaScript ou URL.

Antes
resultado.innerHTML = "Você buscou: " + q;
Depois
resultado.textContent = "Você buscou: " + q;

Sanitizar

Se o HTML for necessário, filtrar com uma biblioteca como DOMPurify.

Antes
item.innerHTML = texto;
Depois
item.innerHTML = DOMPurify.sanitize(texto);

2. Limitar o estrago

CSP

Política que restringe quais scripts podem ser executados na página.

Content-Security-Policy:
  default-src 'none';
  script-src 'nonce-r4nd0m'

Efeito: onerror e scripts inline são bloqueados.

Cookies protegidos

Usar HttpOnly, Secure e SameSite para reforçar a proteção da sessão.

Set-Cookie: sessao=a1b2c3d4e5;
  HttpOnly; Secure;
  SameSite=Strict

Efeito: document.cookie não enxerga a sessão.

Defesa em camadas

Codificar a saídaimpede que a entrada vire código
Sanitizarremove o que é perigoso do HTML
CSPbloqueia a execução do script
Cookies protegidoslimitam o dano se o script rodar

Regra: nunca confie na entrada do usuário.

Defesa

O mesmo ataque, agora com defesa

Repita os payloads: o resultado muda. Depois desligue as defesas e veja cada camada agindo sozinha.

  1. Clique em "alert()" e em "Roubar sessão"
  2. Desligue "Codificar / sanitizar" e ligue só o CSP
  3. Ligue só o "Cookie HttpOnly": o script roda, mas o cookie vem vazio
