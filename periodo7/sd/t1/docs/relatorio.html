Implementação dos Algoritmos de Eleição de Líder em Anel

Este relatório descreve as decisões de implementação adotadas para o desenvolvimento dos algoritmos de eleição de líder utilizando o simulador SMPL. O foco deste documento é apresentar as estruturas de dados, funções e eventos utilizados nos programas, bem como a forma como a comunicação entre processos foi modelada.

1. Algoritmo Chang-Roberts

chang_roberts.c.txt

Estrutura dos Processos

typedef struct {
    int id;
    int lider;
    int candidato;
} Processo;

A estrutura Processo representa cada nó do anel.

  • id: identificador do processo.
  • lider: maior identificador conhecido pelo processo.
  • candidato: indica se o processo participa inicialmente da eleição.

Todos os processos são inicializados com o líder definido como -1. Em seguida, caso o processo seja um candidato, esse valor é alterado para o seu próprio identificador.

Estrutura das Mensagens

typedef struct {
    int candidato;
} Mensagem;

Cada mensagem contém apenas o identificador do candidato que está sendo propagado pelo anel.

Buffer de Mensagens

Mensagem *buffer;

O vetor de mensagens é necessário para funcionar como uma área de armazenamento temporário (uma "caixa de entrada") para cada processo do anel. Como a simulação é orientada a eventos, quando um nó envia um dado, essa informação precisa ficar retida em algum lugar até que o destinatário seja ativado pelo simulador para processá-la.

A indexação estruturada como buffer[destino] garante que cada processo tenha um espaço exclusivo e reservado para si. Como o fluxo do algoritmo de Chang-Roberts é sequencial e cada nó recebe apenas uma mensagem por vez de seu predecessor imediato, o vetor cumpre perfeitamente o papel de isolar o dado e garantir que ele seja consumido no evento correspondente sem o risco de perda ou sobrescrita.

Função enviar()

void enviar(int origem, int candidato)

Esta função é responsável por encaminhar mensagens para o próximo processo do anel.

O próximo processo é calculado através da expressão: 

(origem + 1) % N

O operador módulo permite que o último processo volte a se comunicar com o primeiro, fechando o anel.

A função realiza três operações:

  1. Armazena a mensagem no buffer do destinatário.
  2. Incrementa o contador global de mensagens.
  3. Agenda um evento de recebimento através de schedule().

Evento start

O evento start representa o início da eleição.

Quando o processo é candidato, ele envia uma mensagem contendo seu próprio identificador.

Evento msg

O evento msg representa a chegada de uma mensagem ao processo.

Quando uma mensagem é recebida existem dois casos principais:

  • A mensagem retornou ao candidato de origem.
  • A mensagem ainda está circulando pelo anel.

Se a mensagem retorna ao processo que a criou, significa que nenhum candidato com identificador maior sobreviveu. Neste caso o processo é declarado líder.

Caso contrário, o processo compara o identificador recebido com o maior líder conhecido.

Se o identificador recebido for maior, a mensagem é repassada.

Se for menor ou igual, a mensagem é descartada.

2. Algoritmo Aleatorizado

randomized.c.txt

Estrutura dos Processos

typedef struct {
    int id;
    int ativo;
    int bit;
    int candidatos;
    int rodada;
} Processo;
  • id: identificador do processo.
  • ativo: indica se o processo continua participando da eleição.
  • bit: valor sorteado na rodada atual.
  • candidatos: quantidade de candidatos observados na rodada.
  • rodada: número da rodada atual.

Estrutura das Mensagens

typedef struct {
    int id;
    int bit;
} Mensagem;

As mensagens precisam transportar tanto o identificador do processo quanto o bit sorteado naquela rodada.

Matriz de Buffers

Mensagem **buffer;

Por que utilizar uma matriz ao invés de um vetor, como no algoritmo de Chang-Roberts? No algoritmo Chang-Roberts, o fluxo de mensagens é mais restrito e linear. Já no algoritmo aleatorizado, todos os processos ativos iniciam uma rodada e transmitem suas mensagens simultaneamente (no evento round). Como cada mensagem deve dar uma volta completa no anel para retornar ao seu criador, um único processo precisará receber e repassar mensagens vindas de múltiplos nós antes mesmo de conseguir processar a sua própria fila no laço de eventos do SMPL.

Se tivéssemos utilizado um vetor simples do tipo buffer[destino], enfrentaríamos um problema crítico de condição de corrida (race condition) e perda de dados. Caso a simulação agendasse a chegada de mensagens de origens diferentes para o mesmo nó de destino no mesmo instante de tempo (ou antes que o destino executasse o seu evento msg para consumir o dado atual), a última mensagem a chegar sobrescreveria a anterior, corrompendo o estado da simulação.

A matriz de buffers resolve este problema ao isolar o armazenamento: a posição buffer[destino][origem] garante um espaço exclusivo e indexado para cada remetente. Dessa forma, o processo de destino consegue reter com segurança as mensagens de cada nó da rede de forma independente, permitindo a circulação paralela de múltiplos pacotes pelo anel sem riscos de colisão ou eliminação de dados.

Função enviar()

void enviar(int origem, int id, int bit)

A função realiza:

  1. Armazena a mensagem no buffer do destinatário.
  2. Incrementa o contador global de mensagens.
  3. Codifica o token
  4. Agenda um evento de recebimento através de schedule().

Codificação do Token

O SMPL permite enviar apenas um valor inteiro como token.

Para transportar simultaneamente origem e destino foi utilizada a expressão: 

token = destino * 1000 + origem;

Posteriormente os valores são recuperados através de: 

destino = token / 1000;
origem = token % 1000;

Evento round

Representa o início de uma rodada da eleição.

Todo candidato sorteia um bit aleatório: 

0 ou 1

Após o sorteio, o processo envia uma mensagem contendo seu identificador e o bit sorteado.

Evento msg

O evento msg representa a chegada de uma mensagem ao processo.

Quando a mensagem retorna ao seu emissor significa que ela completou uma volta inteira pelo anel.

Nesse momento o processo verifica o resultado da rodada.

  • Se foi o único a obter bit 1, torna-se líder.
  • Se todos obtiveram bit 0, a rodada é reiniciada.
  • Se existem vários processos com bit 1, apenas eles continuam.

Mensagens que ainda não retornaram ao emissor são simplesmente encaminhadas para o próximo processo do anel.
